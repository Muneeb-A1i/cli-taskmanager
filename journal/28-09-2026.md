## Worked on

Today I continued working on the task storage part of my CLI task manager in C. I kept using a two-dimensional character array:

```
char tasks[5][30] = {"", "", "", "", ""};
```

This gives the program five task slots, with up to 29 visible characters plus the terminating null character in each slot.

My main focus was learning how to inspect each row in the array and decide whether it is empty. I used a loop to go through all five task slots and tested the first character of each one:

```
if (tasks[i][0] == '\0') {
    printf("Element %d is empty\n", i);
}
```

By the end of the session, this worked correctly. When the task array was empty, the program printed that elements 0 through 4 were empty. This is an important step towards finding the first available slot when the user creates a task.

## Investigated

I spent time understanding the difference between an entire row of the task array and a single character within that row.

- `tasks[i]` refers to one task slot. In many expressions it becomes a pointer to the first character of that task, so it should not be compared directly with `NULL`, `0`, or `'\n'` to test whether the task is empty.
- `tasks[i][0]` refers to the first character in task slot `i`. If it is `\0`, the string is empty.
- `tasks[i][0] = '\0'` assigns an empty-string terminator and changes the array. To test instead, I need `==`:

```
if (tasks[i][0] == '\0')
```

I also experimented with printing the task slots. Using `%d` or `%c` with `tasks[i]` gave warnings because `tasks[i]` is effectively a character pointer when passed to `printf()`. The right format for a task string is `%s`:

```
printf("%s\n", tasks[i]);
```

I confirmed that the task array occupies 150 bytes in total: five rows of 30 characters. I also corrected the code so it compiled cleanly at the end of the session. Earlier warnings showed that values returned by `sizeof()` should be printed with `%zu`, rather than `%d`, because `sizeof` produces a `size_t` value.

## Problems encountered

Today included several useful compiler messages and experiments:

- I tried declaring `char tasks[5][]`, but the compiler explained that in a multidimensional array every dimension after the first must have a size. The program needs to know that each task row is 30 characters wide.
- I used `tasks[i] == NULL`, but the compiler warned that the address of an array row will not be `NULL`.
- I compared `tasks[i]` with `'\n'`, which produced a pointer-versus-integer warning. A newline is a single character, while `tasks[i]` represents a whole row/string.
- I accidentally used assignment (`=`) rather than comparison (`==`) in an `if` condition. The compiler warning helped catch it.
- I briefly typed `nnao` instead of `nano`, and the terminal suggested the correct command.

These errors were useful because they made the structure of a two-dimensional character array clearer: each row is a string, and each position inside that row is an individual character.
