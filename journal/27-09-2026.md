## Worked on

Today I worked on the next part of my CLI task manager in C: storing task names in an array instead of only printing the task name straight after the user enters it.

Yesterday I got fgets() working, so the user could enter a task name with spaces. Today I tried to take that input from create_task() and put it into a tasks[][] array, so the program can remember multiple tasks and list them later.

The behaviour I am aiming for is:

- The user selects “Add Task”.

- The program checks the first space in the task array.

- If tasks[0] is empty, it stores the new task there.

- When the user adds another task, it sees that tasks[0] is no longer empty and checks tasks[1].

- This continues until the array is full.

- The user can choose “List Tasks” to see the tasks that have been added.

## Investigated

I spent time experimenting with different ways of declaring and measuring arrays.

At first, I wrote an array like this:

`char tasks[] = {"Wash Dishes", "Do laundry", "Complete Homework"};`

This caused an “excess elements in char array initializer” error. I learned that a normal char array holds individual characters, whereas multiple task names need either a two-dimensional character array or an array of string pointers.

I then tried a two-dimensional array, including:

`char tasks[][] = {"Wash Dishes", "Do laundry"};`

The compiler explained that every dimension except the first needs a size. That helped me understand why a declaration needs to say how many characters each individual task can hold, for example:

`char tasks[NUMBER_OF_TASKS][TASK_LENGTH];`

I also tested sizeof() to understand the array’s memory layout. With an array containing five task slots of 30 characters each, I got:

total bytes: 150
byte of each element: 30
Number of elements in array: 5

This made sense because 5×30=1505×30=150. I used:

`sizeof(tasks) / sizeof(tasks[0])`

to calculate the number of task slots. I also got warnings because I used %d to print values returned by sizeof(). The compiler said sizeof() returns a long unsigned int, so %zu is the more appropriate format specifier for sizeof values.

I tried declaring an empty array like this:

`char tasks[0][30] = {};`

This compiled with warnings, but it created an array with zero task slots. The program reported zero total bytes and zero elements. The compiler also warned that trying to print tasks[0] could read from memory outside the array. This showed me that, for now, I need to choose a fixed maximum number of tasks rather than starting with an array of size zero.

I also ran into syntax errors while experimenting, including:

- A missing ) in a for loop.

- Using printf() outside a function, which produced errors about “expected declaration specifiers”.

- Trying to use an undeclared variable called names.

- Accidentally compiling main,c instead of main.c, which made the linker say it could not find the file.

- Forgetting that functions need to be closed with } before starting another function.

## Current state

The project is still a work in progress. At the moment, create_task() successfully reads a task name using fgets() and prints it back to the terminal. I have also started setting up the tasks array and working out how many task slots it has.

However, I have not yet successfully copied the text from task_name into a slot in tasks. I also need to fix the structure of the functions and restore the menu code after my array experiments.

I think this is still useful progress because I now understand more clearly that:

- task_name is a temporary character array used for one piece of user input.

- tasks needs to be a larger two-dimensional array so it can store several task names.

- Each row, such as tasks[0], represents one task.

- The program needs a loop to find the first empty row before saving a new task.

- A fixed-size array must have a real capacity; an array with zero rows cannot store tasks.
